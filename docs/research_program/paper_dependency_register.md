# Paper dependency register (human-readable)

**Machine-readable twin:** `paper_dependency_register.csv`  
**Statuses:** `active` = RP-P1 only; all others `planned` (not preregistered, implemented, or validated).

## Dependency diagram

```
RP-P1 (active; Layer 1 doctrine)
   │
   ├──► RP-P2 (planned; SLAPA architecture + content validity)
   │       │
   │       └──► RP-P3 (planned; field validation Layers 2–4)
   │               │
   │               └──► interventions / practice manual / policy briefs (later)
   │
   └──► RP-P4 (planned; detectability companion; Domain B)
           └──► optional Domain B field module (after architecture exists)
```

## RP-P1 — Documentary audit (active)

- **Objective:** Audit *executability engagement* in authoritative guidance.  
- **Spine:** Protective-action executability only.  
- **Does not measure:** school preparedness, effectiveness, or detectability.  
- **Enables:** RP-P2 (required); RP-P4 shares infra only.

## RP-P2 — SLAPA architecture (planned)

- **Objective:** Domain architecture + content validity (+ cognitive testing; optional tiny feasibility pilot).  
- **Depends on:** RP-P1 findings (under-specification map).  
- **Does not claim:** psychometric validation or Layer-5 outcomes.

## RP-P3 — Field validation (planned)

- **Objective:** Reliability, structural/construct validity, cautious group comparisons with safeguards.  
- **Depends on:** RP-P1 + RP-P2.  
- **Compares organisational conditions**, not pupil dangerousness or inherent school-type safety.

## RP-P4 — Detectability companion (planned)

- **Objective:** Independent Branch B / Domain B programme.  
- **Forbidden:** modelling as demand–capability fit; merging with RP-P1 spine.  
- **Capacity note:** start only when resources permit (Priority 4).
